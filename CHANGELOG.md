# Changelog

## 0.3.46
- A tool-using reply keeps the model's code. Indentation inside a fence, blank lines, and a short "Done." stay. Only an exact tool-log line is removed. A review, a revision, and the last no-tools answer do not flatten that text.
- A restart in the middle of a turn does not leave an empty assistant bubble. The row says "Interrupted, resuming", and a reply that already had words is kept. "Picked up where it stopped." still follows when resume is on.
- After the person asks another bot, that reply is context for one last call with no tools. The answer is written in this bot's own words and saved on the turn. Resume, including a resume after a restart, leaves YOLO on for the whole bot. It stays until the owner turns it off or it expires.
- A code fence keeps its indentation. A tool log is removed only when the whole line is that log, and text inside a fence is left as the model wrote it. A chat, a lookup, and a search-and-answer do not send another bot unless the person asked. "This was not verified." is not added to the answer. That caveat stays in the model's own words or on the unverified status line.
- A turn always leaves an answer. Chat, a lookup, and a search-and-answer are not reviewed. A review runs at most once, and only after a file change, a test run, or three or more steps that changed state. The done-gate does not start another review. If the turn would end with no answer, one last call with no tools asks for the answer in the bot's own words, or a plain sentence says the turn ended before an answer was written. Another bot's reply is an input, not the answer. A turn searches the web at most twice, then answers. A message after a finished answer does not pause.
- A finish that arrives after the answer is already on screen is rejected at most once, and that answer ends the turn. Twenty seconds with no model or tool activity after that answer ends the turn and clears the live status. "The file is … in …" is added only when the answer does not already name the file, and it is part of the answer before the turn ends.
- A denied card applies to that turn only. A card that expires is not a denial, and neither one is saved on the bot. Settings has Clear remembered decisions, which drops Always approvals and any older denial.
- While /yolo is on for this bot, every approval gate allows the action and shows no card. That includes Strict, the shell allow-list, a file outside the bot folder, a secret, a download, a web fetch, an MCP call, asking another bot, and saving a routine. The bot's own notes, including MEMORY.md and USER.md, can be read in every mode. The audit log still records what ran. YOLO is stored on the bot, so it survives a restart and covers every chat of that bot. Settings can turn YOLO on for every bot. A routine's own later run and a child agent stay gated. Hermes's catastrophic floor still blocks unless EASYAGENT_YOLO_FLOOR is off: a root, system, or home wipe, mkfs, dd or a redirect onto a raw disk, a fork bomb, kill -1, and shutdown or reboot. The refusal says it is a catastrophic command blocked even in YOLO. It does not say a card is waiting. Strict and the default mode are unchanged.
- A reply that has just finished shows its code highlighted, in the same row. While the reply is still arriving, code stays plain. Existing rows do not move.
- One live status line per turn, updated in place. Finished steps, including a tool step and "Asked … → got reply", stay above it. A second Writing timer does not appear.
- Reasoning from each model call is kept once, and the first word of the answer does not land in the thinking box. The thinking box closes when the answer starts. A finished turn clears Writing, and the view stays at the bottom unless you scroll up.

A GitHub-hosted runner is skipped the same way: it reports an interactive window station, but a restricted token cannot open that desktop and the child exits STATUS_DLL_INIT_FAILED (0xC0000142). A locked screen or a disconnected desktop on a real logon is inconclusive, so the check does not pass without testing the fallback. A real interactive logon still runs that probe, and exit 0xC0000142 there is a failure. When that fallback cannot start, the command is not run outside the sandbox. The Windows CI job runs Python 3.11 and 3.12 without cancelling the other when one fails.
- A Windows shell command that starts with a quoted program is passed to PowerShell with the call operator, so `"C:\\Python\\python.exe" -c "..."` runs. The safety rules judge that final string, not the text from before the call operator was added.
- Quotes, empty quotes, backticks, carets, and backslash escapes collapse inside a shell word before every verb check, on PowerShell, cmd, and bash. A leading `&` or a dot-source `.` is the program that follows. These already classified as allow, and did run, on 0.3.12: bash `r""m -rf /` and `'r'm -rf /`, cmd `"format" C:`, and PowerShell `."format" C:`. `format /q /y C:` was the same hole.
- A command that runs another command is judged as that inner command: `cmd /c` and `/k`, a shell `-c`, `eval`, `exec`, `xargs`, `env`, `nohup`, `sudo`, `doas`, `time`, PowerShell `-Command`, `Invoke-Expression`, `Start-Process`, `start`, and `Invoke-Command`. Quoting is undone for that shell, and the same rules run again up to a depth limit. Past that limit, the command waits. A program that is not a plain literal after that read — a call like `& (gcm format)`, `iex` of a concatenated string, or a variable in the program position — waits, and so does a command the tokenizer cannot read. A literal `("format")` or `(format)` is `format`. These already classified as allow, and did run: `cmd /c "\"format\" C:"`, `eval 'rm -rf /'`, `.("format") C:`, `&("format") C:`, `& (format) C:`, `& (gcm format) C:`, `iex ('for'+'mat C:')`, and `& ('for'+'mat') C:`.

The same scan covers `perl -e`, `ruby -e`, `php -r`, `lua -e`, `node -e`, `deno eval`, `python -c`, and `pwsh -c`. An alias or function on the same line is judged as its target, and a target that cannot be read waits. A pipe into a shell waits, and decoding into a shell (`base64 -d | sh`) is refused. These already classified as allow, and did run, on 0.3.12. `find` with only a name pattern, `eval "$(ssh-agent)"`, `pyenv init`, a conda shell hook, `brew shellenv`, `xargs` of a command that does not delete, and `nohup npm start &` stay allowed.
